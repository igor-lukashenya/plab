# plab: R&D research template, design (v2)

Date: 2026-11-25
Status: draft v2, awaiting approval (v1 approved earlier; v2 adds notes, cases, media formats, workflow skills, CI)

## Intent and why

plab is an empty repo. The owner runs R&D research projects; the reference is an earlier
LLM PoC research at `<reference-research-repo>`
("the reference repo", read-only). Every research needs the same scaffolding and the same
habits: cases investigated one by one, notes taken along the way, summaries written from
those notes, and media (a general presentation, announcements, social posts, short result
digests, shorts) produced quickly with Hyperframes.

plab becomes a **GitHub template repository**: per research the owner clicks "Use this
template", runs `make init`, and starts on research instead of scaffolding. It is also
operated by AI agents, so it carries agent instructions and skills that work across tools.

## Goals

- Clean skeleton from the reference's structure, MkDocs, docs layout and Makefile, with no research-specific content.
- `cases/` (not `apps/`): each investigation is created with a command and tracked by a `case.yaml`.
- `notes/`: fast note capture (skill, script, or by hand) and a synthesis skill that turns notes into summaries.
- `media/`: generic, format-based Hyperframes projects with a shared engine; captions and audio are separate, optional tracks.
- Workflow skills usable from any common AI tool; deterministic scripts do the file work.
- Prompt library, results table generated from cases, CI (tests plus GitHub Pages), `make doctor`.

## Non-goals

- No research content (LLM, PoC, .NET, case names, screenshots, renders, audio).
- No engine-as-package, no Copier/Cookiecutter, no `{{ }}` placeholders: the template runs as-is.
- No Git LFS, dev container or database.
- Reference repo is never modified.

## Anti-goals

- Research- or event-specific wording in the template (grep check below).
- Windows-only or machine-specific commands.
- A template that needs manual edits before it builds.
- Skills that only work in one tool.

## Constraints

- Debian/Ubuntu/WSL, Node 22+, Python 3. `make slides-deps` needs sudo (owner runs it).
- Hyperframes pinned once: `HF_VERSION ?= 0.8.138` in the Makefile.
- Scripts are Python stdlib-only, except `scripts/results.py`, which needs PyYAML (installed with MkDocs by `make install`).
- Repo has no commits yet. Files only; no commits, remotes or GitHub settings changed.
- Sentinel defaults: title `Research Template`, slug `research-template`.

## Approaches considered

1. **GitHub template repo plus init script (chosen).** Simple, no extra tools. Later template fixes do not propagate to existing repos.
2. Copier/Cookiecutter: prompts and `copier update`, but needs a tool and placeholder syntax; template not runnable as-is.
3. Template plus engine as a package: fixes propagate, but packaging overhead is not justified yet.

## Design

### Layout

```
plab/
├── CLAUDE.md, AGENTS.md          # identical; AGENTS.md is a symlink to CLAUDE.md
├── README.md, Makefile, mkdocs.yml, .gitignore
├── .github/workflows/{ci.yml,pages.yml}
├── .claude/skills/<name> -> ../../skills/<name>   # symlinks for Claude Code
├── skills/                       # canonical skills, one folder each with SKILL.md
│   ├── note/ synthesize-notes/ new-case/ write-case-report/ new-media/
├── scripts/                      # init, new_case, note, results, new_media, doctor (.py)
├── tests/                        # unittest
├── notes/{README.md,_template.md,inbox/}
├── prompts/{README.md,_template.md}
├── cases/{README.md}             # <slug>/{case.yaml,README.md} created by make new-case
├── docs/
│   ├── index, executive-summary, research-definition, research-overview, research-report,
│   │   research-report-summary, cases-ideas-and-definition, case-report-template,
│   │   blog-post-ideas, blog-post-drafts, event-ideas, references  (.md, headings plus one guidance line)
│   ├── results.md                # GENERATED by make results
│   ├── cases/<slug>/case-report.md
│   └── superpowers/              # design docs and plans, excluded from the site
└── media/
    ├── README.md                 # formats and workflow, written for agents and humans
    ├── shared/                   # engine.py, theme.css, export_pdf.py, formats.py, templates/<format>/
    ├── deck/ invite/ social/ digest/ shorts/ explainer/   # <format>/<name>/ projects; one example each as needed
    └── kit/                      # small committed folder for final approved files
```

### Cases

- `make new-case NAME=slug TITLE="..."` creates `cases/<slug>/{case.yaml,README.md}`, copies `docs/case-report-template.md` to `docs/cases/<slug>/case-report.md`, and inserts a nav line at `# new-case:insert` in `mkdocs.yml`. Fails loudly (no partial writes) on invalid slug (`^[a-z0-9]+(-[a-z0-9]+)*$`), existing case, or missing marker.
- `case.yaml` fields: `title`, `slug`, `status` (`planned|win|mixed|fail|manual`), `stack`, `tools` (list), `models` (list), `iterations` (int), `time_spent_hours` (number), `started` (date), `report` (relative path).
- `make results` reads every `cases/*/case.yaml` and writes `docs/results.md` (table sorted by title, with status counts). Exits non-zero on a case with an invalid `status` or missing required field.

### Notes

- `notes/inbox/YYYY-MM-DD-HHMM-slug.md`, frontmatter: `title`, `date`, `type` (`observation|question|decision|quote|result`), `case` (optional slug), `tags` (list), `status` (`raw|used`), `starred` (bool, default false). Raw notes are not published; summaries go to `docs/`.
- `make note TITLE="..." [TYPE=] [CASE=] [TAGS=a,b] [BODY="..."]` creates the file (no AI needed). Validates `CASE` against `cases/`.
- Skill `note`: captures a note from chat via `scripts/note.py`. Skill `synthesize-notes`: reads notes filtered by case or tag (all by default, `starred` only on request), drafts a section into the matching `docs/` file, sets used notes to `status: used`.

### Cross-tool skills

`skills/<name>/SKILL.md` is the single source (frontmatter `name`, `description`, then instructions that call the scripts). Claude Code reads them via `.claude/skills/` symlinks. `AGENTS.md` lists every skill with its path and one-line purpose and states the rules, which covers tools that read `AGENTS.md`. Not every tool's own skill-folder convention is verified; baseline is `AGENTS.md` plus the Make commands. Skills: `note`, `synthesize-notes`, `new-case`, `write-case-report` (fills a report from `case.yaml` and notes for that case), `new-media`.

### Media

- Project handle `M=<format>/<name>`. Formats and defaults live in `media/shared/formats.py`:
  `deck` 1920x1080 (slides plus speaker script), `invite` 1920x1080 (teaser video, poster via still), `social` 1080x1350 (post), `digest` 1920x1080 (1-2 min results summary), `shorts` 1080x1920, `explainer` 1920x1080 (animated mechanism scene).
- `make new-media FORMAT=deck NAME=main` copies `media/shared/templates/<format>/` to `media/<format>/<name>/` (static Hyperframes files, `build.py`, `narration/`, `assets/`). Fails on unknown format or existing project.
- Theme gets per-format size tokens (the reference theme is tuned for 1920x1080 only).
- Generated per project (git-ignored): `index.html`, `compositions/`, `styles/theme.css`, `notes.html`.
- Targets (all take `M=`): `media-build`, `media-dev`, `media-check`, `media-render`, `media-png [AT=seconds]`, `media-pdf` (deck only), `media-audio`, `media-captions`; plus `media-check-all`.
- **Captions and audio are separate optional tracks.** The script is `narration/*.txt`. `media-audio` generates voiceover wavs for that project only (local Kokoro, venv from `slides-venv`). `media-captions` writes `.srt` files (from the script timing, or Whisper transcription of existing audio). Default builds and renders are clean. `CAPTIONS=1` burns captions in, `AUDIO=1` mixes voiceover in. `media-render` also writes a sidecar `renders/<name>.srt` so players can toggle subtitles.

### Makefile

Families: docs (`install serve build clean`), `init`, `new-case`, `results`, `note`, `new-media`, `media-*`, `slides-deps slides-venv slides-install`, `doctor`, `test`, `help`. `clean` is `rm -rf site`. `help` lists every target (generated from `##` comments, so it cannot go stale).

### Other pieces

- `prompts/`: one file per prompt from `_template.md` (`when to use`, `prompt`, `result note`, `case` link).
- `make doctor` (`scripts/doctor.py`): checks Node >= 22, Python 3, `ffmpeg`, `espeak-ng`, Chrome libs, `hyperframes@$(HF_VERSION)` reachable, MkDocs; prints the fix command per missing item; exits non-zero if anything required is missing.
- CI: `ci.yml` runs `python3 -m unittest`, `mkdocs build --strict` and `make media-build` for every project on push/PR; `pages.yml` deploys the MkDocs site to GitHub Pages on `main`.
- `make init NAME= TITLE=`: replaces sentinels in `mkdocs.yml`, `README.md`, `docs/index.md`, `media/README.md`, media example `build.py` config blocks and `package.json` names; marker `.template-initialised` stops a second run; plain `str.replace` (safe for `&`, `/`, quotes).
- Render policy: renders and audio are git-ignored; finished approved files go to `media/kit/`.

### Agent instructions

`CLAUDE.md`/`AGENTS.md`: purpose, layout, command cheat-sheet, skills list, rules (never hand-edit generated files; slide order renames numbered narration files so update them; run `make media-check M=...` before calling a deck done; use `make new-case`/`new-media`/`note`, not manual folders; captions and audio are optional and off by default), docs conventions, and how to start a new research. `media/README.md` explains each format, sizes, and the captions/audio workflow.

## Verification (definition of done)

1. Unit tests pass for `init`, `new_case`, `note`, `results`, `new_media` (edge cases: second `init`, special characters in title, bad slug, existing slug, missing nav marker, bad case status, unknown format).
2. On a scratch copy: `make init`, `make new-case`, `make note`, `make results`, `make new-media` for each format, `mkdocs build --strict`, `make media-build` for each project all succeed.
3. Chrome-dependent checks (`media-check`, `media-png`, `media-render`, `media-audio`) run if `make doctor` is green; otherwise reported as unverified with the exact commands.
4. Leak grep for `LLM|PoC|\.NET|meetup|talk|announcement|Opus|GPT|Copilot|SpecKit|ecommerce|fintech` outside `docs/superpowers/` returns nothing (the Hyperframes boilerplate may be reviewed manually).
5. `AGENTS.md` equals `CLAUDE.md`; every skill has `name` and `description` and its `.claude/skills` symlink resolves; every Make target named in `CLAUDE.md` exists.
6. Reference repo `git status` unchanged.

## Builder-check decisions (my calls)

- **Port, not redesign.** The reference repo is readable by the builder and its engine (`presentation/shared/engine.py`, 199 lines, generic), theme, PDF export, Hyperframes project files and Makefile deck targets are ported and generalised. The reference's `build.py` shows the contract: slides are `add(name, section, duration, html)` calls, `build(OUT)` writes `index.html`, `compositions/`, `styles/theme.css` and `notes.html`. Static per project: `package.json`, `hyperframes.json`, `meta.json`, `build.py`, `narration/`, `assets/`. Generated: everything else. Read it first.
- **One scene model.** Formats differ by size, default duration, example content and which targets apply, not by engine. `media-pdf` applies to `deck` only; `media-png` to any format; for `social` the primary output is `media-png`. Every format gets one committed example project named `example` (`media/<format>/example/`), so CI and verification always have a project to build. `make new-media` copies from `media/shared/templates/<format>/`, which is the same content as the example.
- **`media-build` is pure Python/HTML generation**: no Chrome, no ffmpeg. CI runs only it, plus unit tests and MkDocs. Chrome/Node-based checks stay local.
- **`make init`** is string replacement only; `NAME` is the slug. It keeps the example media projects and `docs/superpowers/` untouched. `.template-initialised` is committed in the new repo (that is how it blocks a re-run).
- **Excluding `docs/superpowers/`** uses MkDocs `exclude_docs`. Nav lists every site page; `mkdocs build --strict` must pass.
- **Symlinks:** `AGENTS.md` and `.claude/skills/*` are symlinks. Supported hosts: Linux, macOS, WSL. Native Windows checkout is not supported.
- **`case.yaml` required fields:** `title, slug, status, stack, tools, models, iterations, time_spent_hours`. Optional: `started` (ISO date), `report` (relative path, defaults to `docs/cases/<slug>/case-report.md`). `manual` is an ordinary status. `new-case` writes defaults (`status: planned`, empty lists, zeros).
- **Captions/audio dependencies:** default captions come from script timing (`engine.derive_cues`), no extra install. Transcribing existing audio uses `hyperframes transcribe` as in the reference `slides-captions` target (needs `slides-venv`); unverified if the owner has not run it.

## Left to the builder

- `doctor` check implementation details; CI workflow details.
- Exact `note` and `results` output formatting beyond the fields above.
- Trimmed `.gitignore` contents.
