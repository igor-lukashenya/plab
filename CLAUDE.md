# Research Template

## Purpose

A template repository for research projects: cases investigated one by one, raw notes captured along the way, summaries and case reports written from those notes, and media (decks, videos, stills) built from the results. Everything is driven by `make` targets.

## Layout

```
├── cases/<slug>/        # case.yaml and README.md per case (make new-case)
├── docs/                # MkDocs source: summaries, results, docs/cases/<slug>/case-report.md
├── notes/inbox/         # raw notes with YAML frontmatter (make note)
├── prompts/             # prompt library, one file per prompt
├── media/<format>/<name>/  # media projects (make new-media); media/shared is the engine
├── scripts/             # Python helpers behind the Makefile
├── skills/<name>/SKILL.md  # agent skills (linked from .claude/skills/)
├── tests/               # unit tests (make test)
├── mkdocs.yml, Makefile, README.md
```

## Commands

Run `make help` for the always current list.

| Group | Targets |
|-------|---------|
| Docs site | `make install`, `make serve`, `make build`, `make clean` |
| Quality | `make test`, `make doctor` |
| Research | `make new-case NAME=... [TITLE=...]`, `make note TITLE=... [TYPE= CASE= TAGS= BODY=]`, `make results` |
| Template | `make init NAME=... [TITLE=...]` |
| Media scaffold | `make new-media FORMAT=... NAME=...` |
| Media build | `make media-build M=<format>/<name>`, `make media-dev`, `make media-check`, `make media-check-all` |
| Media output | `make media-render`, `make media-png`, `make media-pdf` (decks only) |
| Media extras | `make media-audio`, `make media-captions`, `make slides-deps`, `make slides-venv`, `make slides-install` |

## Skills

- `skills/note/SKILL.md`: capture a raw note.
- `skills/synthesize-notes/SKILL.md`: turn notes into a section of a docs file.
- `skills/new-case/SKILL.md`: scaffold a case.
- `skills/write-case-report/SKILL.md`: fill a case report from `case.yaml` and its notes.
- `skills/new-media/SKILL.md`: scaffold a media project.

## Rules

- Never hand-edit generated files: `media/*/*/index.html`, `media/*/*/compositions/`, `media/*/*/styles/theme.css`, `media/*/*/notes.html`. Change `build.py` and rebuild.
- Reordering slides renames the numbered narration files (`narration/NN-name.txt`, and any matching audio and captions). Update them with the new order.
- `media/kit/` holds approved finals and is committed; renders, audio and captions are git-ignored, so copy an approved render there.
- Run `make media-check M=<format>/<name>` before calling a media project done.
- Use `make new-case`, `make new-media` and `make note`. Never create those folders or files by hand.
- Captions and audio are optional and off by default. Pass `CAPTIONS=1` or `AUDIO=1` on the command line only, never as defaults.
- When editing media compositions, invoke the `/hyperframes` skill first if it is installed.
- Do not copy the Hyperframes boilerplate agent files into media projects.

## Git conventions

Enforced by `scripts/gitcheck.py`, the hooks in `.githooks/` (enable them once with `make hooks`; `make init` does it for you) and the `conventions` CI job on pull requests.

- Branches: `main`, or `<type>/<kebab-description>` with at most 50 characters in the description. Types: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`, `build`, `perf`, `style`, `revert`. Valid: `feat/note-search`, `fix/123-init-marker`. Invalid: `wip`, `Feature/Note`, `feat/Note_Search`.
- Commits follow Conventional Commits: `type(scope)!: subject`. Scope and `!` are optional, the type is lowercase, no trailing period, the whole header at most 72 characters. Valid: `feat(notes): add note search`, `fix: reject empty title`, `refactor(media)!: rename build flags`. Invalid: `Added search`, `Feat: x`, `fix: done.`. Merge, `Revert "..."` and `fixup!` commits are allowed as git writes them.
- Pull requests are squash-merged, and the PR title becomes the commit message, so write it as a commit header.
- Agents: create a conventionally named branch before committing, and never commit on `main` unless the owner says so. Never use `--no-verify`. `SKIP_GITCHECK=1` is the owner's escape hatch, never yours.

## Docs conventions

- Docs are Markdown under `docs/`, built by MkDocs with `make build` (strict: broken links fail).
- Case reports live at `docs/cases/<slug>/case-report.md`, shaped by `docs/case-report-template.md`.
- `docs/results.md` is generated by `make results`; do not edit it by hand.
- Notes are raw and unpublished; summaries drawn from them go into `docs/`, and used notes get `status: used`.

## Starting a new research

1. Use this repository as a template on GitHub (tick *Template repository* in the repository settings of the original so the button appears).
2. Clone the new repository and run `make install`, then `make doctor`.
3. Run `make init NAME=my-research TITLE="My Research"` once (it also enables the git hooks; run `make hooks` yourself in a repo that already exists).
4. Add cases with `make new-case`, capture notes with `make note`.
5. To publish the docs, open *Settings -> Pages -> Source* on GitHub and choose *GitHub Actions*.
